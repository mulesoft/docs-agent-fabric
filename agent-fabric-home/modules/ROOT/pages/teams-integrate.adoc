= Integrate with Microsoft Copilot and Teams
:keywords: microsoft teams integration, mulesoft agent, teams bot, mcp server, anypoint platform, enhanced experience

Get alert notifications directly in Teams channels through the MuleSoft for Teams app, and use the MuleSoft plugin to manage APIs, agents, LLMs, MCP servers, governance strategies, policies, gateways, observability, and cost optimization across Anypoint Platform in Microsoft Copilot. The plugin provides full capabilities of the xref:mulesoft-mcp-server::reference-mcp-tools-platform.adoc[MuleSoft Platform MCP Server].

* <<mulesoft-plugin, Plugin setup>>: Provide Copilot access to the MuleSoft Platform MCP Server.
+
A Microsoft admin installs the MuleSoft plugin through the Microsoft plugin registry to make the plugin available to Microsoft Copilot Chat and Copilot Cowork. Copilot is available from Microsoft Teams and other Microsoft products.

* <<connect-teams-tenant, App setup>>: Provide alerts from the enhanced MuleSoft experience to Teams channels.
+
A Microsoft admin who also has an Organization Administrator permission to Anypoint Platform connects the Microsoft Teams tenant to your Anypoint organization, chooses Teams channels that receive alerts, submits the app for review from the enhanced MuleSoft experience, and approves the app in Microsoft Teams Admin Center.

[[mulesoft-plugin]]
== Connect MuleSoft Copilot to the MuleSoft Platform MCP Server

Use the MuleSoft plugin to get access to the full capabilities of  MuleSoft Platform MCP Server from Microsoft Copilot Chat and Copilot Cowork.

Prerequisite: 

* MS 365 Copilot (Premium) license is required. If the plugin is blocked or unavailable, a Microsoft admin can assign the license or enable the plugin.
* An Anypoint Platform account with tool-specific permissions described in  xref:mulesoft-mcp-server::reference-mcp-tools-platform.adoc#command-summary[Command Summary].

[NOTE] 
====

* The MuleSoft plugin relies on generative AI, which can produce inaccurate or harmful responses. Review for accuracy and safety before using.
* Procedures in this section reflect a Microsoft UI experience that is subject to change. For the latest information, refer to the https://learn.microsoft.com/en-us/[official Microsoft documentation].
====

[[plugin-discover]]
=== Make the Plugin Discoverable 

Using the Microsoft 365 admin center, a Microsoft admin deploys the MuleSoft plugin from the Microsoft plugin registry to make it available across supported experiences, such as Copilot Chat and Copilot Cowork.

. Open the Microsoft 365 admin center. 
. Navigate to *Agents* > *Tools* > *Registry* to install the app and make it available to users or groups.
+
Alternatively, if users have requested access, review and approve access under *Agents* > *Tools* > *Requests*.
. Navigate to *Agents* > *Settings* and select *Allow external publishers*. 
+
If external publishers aren't allowed, the plugin will be locked and unavailable to users.

[[plugin-connect-cowork]]
=== Connect to the MuleSoft Plugin from Copilot Cowork

After the Microsoft admin deploys the MuleSoft plugin, users can connect to MuleSoft from Copilot Cowork.

. Open *Copilot*, and navigate to *Plugins*.
. Click the *Cowork* tab in *Plugins*, and click the MuleSoft plugin (located under *Added*).
. Click *Connect*, and log in with Anypoint Platform credentials. 
+
The app displays a *Connected* status when it's ready to use.

[[plugin-connect-chat]]
=== Connect and Use the MuleSoft Plugin from Copilot Chat

After the Microsoft admin deploys the MuleSoft plugin, users can connect to MuleSoft from Copilot Chat.

. From Copilot, navigate to *Plugins* > *Chat*. 
. Find and open the MuleSoft plugin  (located under *Added*).
. In the plugin, type `Connect to MuleSoft` to initiate the connection process. 
+
The plugin indicates whether the connection to MuleSoft Anypoint Platform is successful.

=== Prompt the MuleSoft Plugin from Copilot

After successfully connecting the MuleSoft plugin in Copilot, users can prompt Copilot to invoke MuleSoft Platform MCP server tools described in xref:mulesoft-mcp-server::reference-mcp-tools-platform.adoc[].

. From Copilot, navigate to *New*. 
. Enter a prompt for the MuleSoft Platform MCP server by:

 * Asking a natural-language question without invoking an MuleSoft tool directly. 
+
Examples: `Use MuleSoft` to get a list of common MuleSoft prompts or `Use MuleSoft to list APIs and instances` for more specific information.
 * Typing `/` in the prompt box to pick a specific MuleSoft tool before entering your prompt.

[[connect-teams-tenant]]
== Get Alert Notifications in Microsoft Teams

The MuleSoft for Teams app sends alert notifications from the enhanced MuleSoft experience to Microsoft Teams channels.

A Microsoft admin makes the app available to Teams by completing these steps:

* <<grant-admin-consent>>
* <<approve-app>>
* <<configure-notification-channels>>

NOTE: Each MuleSoft organization can connect to only one Microsoft Teams tenant, and each tenant can connect to only one MuleSoft organization.

Admins can also <<disconnect-teams, disconnect the MuleSoft for Teams app.>>.

[[grant-admin-consent]]
=== (1) Grant Admin Consent to the MuleSoft for Teams App

A Microsoft admin must complete this procedure the first time the app is connected to your tenant. Admin consent registers the MuleSoft for Teams app in your tenant on behalf of your whole organization, so other users aren't prompted to review the permissions.

Prerequisite: Organization Administrator access to Anypoint Platform and a Microsoft admin account is required to complete this procedure. You'll log in to the enhanced experience with Organization Administrator credentials to access the app in the enhanced MuleSoft experience, and you'll sign in with a Microsoft admin account to grant consent for connecting the app to Teams.

. Log in to https://omni.mulesoft.com/[enhanced MuleSoft experience]. 
. Go to *Notifications* > *Settings* > *Teams*.
. In *Teams Setup*, click *Connect* in the *MuleSoft for Teams* card.
. Use your Microsoft admin account to log in.
. On the *Permissions requested* page, accept _all_ the permission scopes:
+
* Submit application packages to your organization's catalog and cancel pending submissions.
* Sign in and read your profile.
* Maintain access to data you have given it access to.
+
For details about each permission, see <<microsoft-graph-permissions>>.
+
IMPORTANT: Removing permissions after installation can cause the app to malfunction. If you plan to change permissions after installing the app, consult your account team.
. Select *Consent on behalf of your organization*.
. Click *Accept*.
+
You return to *Notifications* > *Settings*. The *Teams Setup* section shows *Not Installed*, and the *MuleSoft for Teams* card shows *Submitted for review*. The integration remains inactive until a Teams admin <<approve-app, approves the app in Microsoft Teams Admin Center>>.

[[approve-app]]
=== (2) Approve and Publish the App in Microsoft Teams Admin Center

After the app is submitted for review, a Microsoft admin must publish it so users in your organization can add it.

. Log in to Microsoft Teams Admin Center.
. Go to *Teams apps* > *Manage apps*.
. Search for the MuleSoft app by name and select it.
+
The app details page shows who submitted the app and a *Pending action* status.
+
NOTE: The *Pending approval* count on the *Manage apps* page can take time to update. Search for the app by name instead of relying on this count.
. Click *Publish*.
+
Microsoft Teams Admin Center confirms that the app is published. It can take a few hours for the app status to update.

After the app is published and connected, *Notifications* > *Settings* > *Teams* shows *Installed*, and the *MuleSoft for Teams* card shows *Connected to _<organization-name>_*.

You can now <<configure-notification-channels, add the app to channels in Teams>>. 

[[configure-notification-channels]]
=== (3) Connect the App to Channels in Teams

After the MuleSoft for Teams app is installed, a Microsoft admin connects the app to Team channels. 

You can add only standard channels.

. In Teams, add the app to Teams channels.
+
This preliminary step makes the channels available for enablement in the MuleSoft for Teams app.
. Enable the added channels through the MuleSoft for Teams app: 
.. Log in to https://omni.mulesoft.com/[enhanced MuleSoft experience] to associate the channels with the Teams app. 
.. Go to *Notifications* > *Settings* > *Teams*.
.. In *Notification Channels*, click *Connect Microsoft Teams*.
.. Select your Microsoft account.
+
You return to *Notification Channels*, which now shows a search field.
.. In *Search teams or channels*, enter the name of a team or channel.
.. Select the channels that receive notifications.
.. Click *Add* to add the selected channels.
+
The channels appear under *Channels Enabled for Notifications*, grouped by team. To remove a channel, click the *X* next to it.

To route specific alerts to these channels, see xref:alerts-configure-notifications.adoc[].

[[disconnect-teams]]
=== Disconnect the MuleSoft for Teams App

Admins can disconnect the MuleSoft for Teams app. 

NOTE: After disconnecting, it can take a couple of hours before an admin can reinstall the app. 

. Log in to https://omni.mulesoft.com/[enhanced MuleSoft experience].
. Go to *Notifications* > *Settings* > *Teams*.
. Click *Disconnect* in the *MuleSoft for Teams* card.
. Confirm the disconnection. This immediately revokes MuleSoft's access to your Teams tenant and stops all notifications.
+
The MuleSoft app remains in Microsoft Teams Admin Center. To fully remove it, a Teams admin must uninstall it from the Admin Center, or right-click the app in Teams and select *Uninstall*.

[[microsoft-graph-permissions]]
== Microsoft Graph Permissions

The MuleSoft for Teams app requires the following Microsoft Graph permissions. A Teams admin grants these permissions once, on behalf of the organization, during <<grant-admin-consent>>. Use this information when your security or IT team asks for justification before approving the app installation.

[cols="2,1,3", options="header"]
|===
|Permission |Type |Purpose

|`AppCatalog.Read.All`
|Application
|Verifies that the MuleSoft app is properly published in your Teams app catalog. Without this, the app cannot confirm its own availability, and users see silent failures instead of actionable setup errors.

|`AppCatalog.Submit`
|Delegated
|Submits the MuleSoft app package to your organization's app catalog for review, and cancels pending submissions. A Teams admin must approve and publish the submitted app in Microsoft Teams Admin Center before users can add it.

|`Channel.ReadBasic.All`
|Application
|Delivers API alerts and deployment notifications to specific channels you configure. The app reads channel names and IDs to resolve routing rules. It reads channel metadata only — not message content.

|`Team.ReadBasic.All`
|Application
|During setup, lets you map MuleSoft environments and business groups to specific teams without manually looking up team IDs. Read-only access to team names and descriptions — no access to members or content.

|`User.Read`
|Delegated
|Standard sign-in permission. The app reads basic profile information, such as name, email, and company, to map the Teams user to the correct Anypoint Platform identity and enforce role-based access control. It doesn't access contacts, calendars, or other profile data.

|===

[[security-data-compliance]]
== Security, Data Retention, and Residency

* *Hyperforce and data boundaries*: The MuleSoft Agent respects your designated Hyperforce region. Install the regional app for Teams that corresponds to your region. Customer data never leaves your designated Hyperforce boundary.
* *Data retention and compliance*: Data retention policies, data removal, LLM data tenancy, and infrastructure details are covered in the applicable Salesforce Security, Privacy, and Architecture (SPARC) documentation. Customer data is securely deleted upon expiration of the applicable retention periods in accordance with SPARC guidelines. For more information, see the https://www.salesforce.com/company/legal/trust-and-compliance-documentation/[Salesforce Trust and Compliance Documentation].
